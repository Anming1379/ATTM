# MIDI → ATTM 导入：功能设计

> 状态：已实现（v0.3.0），下面第 11 节的取舍已按讨论结果定稿
> 目标版本：v0.3.0
> 相关代码：`Core/Midi/*`、`Core/Syntax/*`、`MainWindow.xaml.cs`

---

## 1. 一句话目标

把任意 `.mid` / `.midi` 文件转成 ATTM 能直接播放、能继续手动改的 `.attm` 文本，
**转出来的文本必须 0 语法错误**（宁可丢音乐信息，也不能生成解析器不认的东西）。

触发方式两种：

```text
工具栏一个导入按钮  ->  选文件  ->  「MIDI 导入」对话框（选项 + 预览 + 警告）
直接把 .mid 拖进窗口 ->  同一个对话框
```

---

## 2. 先盘清楚 ATTM 语法能表达什么

这是整个功能的难点所在。ATTM 的记谱模型比五线谱简单很多，
下面几条是**硬约束**，转换算法必须绕着它们走。

### 2.1 时间表达的硬约束

| 约束 | 具体规则 | 对导入的影响 |
| --- | --- | --- |
| 拍号 | 只支持 `4/4` 和 `3/4` | 其他拍号要映射或拒绝 |
| 每行段数 | 4/4 只能是 1/2/4 段；3/4 是 1/2/3/4 段 | 分段策略只有几种组合 |
| 每段单元数 | 必须是 1/2/4/8… 个，**段内均分** | 段内网格必须是 2 的幂 |
| 一个音的时值 | 从它开始，到**本行下一个单元开始**为止 | 音的结束点必须落在网格上 |
| 每行最后一个音 | 一直延长到小节末 | 小节末的结束点免费 |
| 休止 `0` | 占一个单元，并**截断前一个音** | 提前收尾只能靠 `0` |
| 最小单元 | `480/32 = 15` tick（三十二分音符） | 网格最细到 1/32 |
| 三连音 | **完全不支持**（段内只能 2 的幂） | 只能近似 + 报警告 |

### 2.2 关键发现：每段的分辨率是独立的

看解析器实现（`AttmParser.ParseSegment`）：

```text
每段自己均分：段长 / 单元数
不同段可以有不同的单元数，只要各自是 2 的幂
```

所以一行可以写成这样（4/4，4 段）：

```text
12,3,0,0
```

```text
第 1 拍：两个八分音符（段内 2 个单元）
第 2 拍：一个四分音符（段内 1 个单元）
第 3、4 拍：休止
```

**这是最重要的自由度**：一段里的长音不会因为别处有十六分音符而被切碎。
转换时要枚举 S（段数）= 1/2/4，给每段单独算最粗的可行网格，然后挑总代价最小的那个。

### 2.3 能表达 / 不能表达的清单

| 音乐信息 | ATTM | 处理方式 |
| --- | --- | --- |
| 音高（12 平均律全部） | 能 | `1-7` + `#` + `+`/`-` 八度，12 个音级全覆盖 |
| 起始时间（1/32 以上对齐） | 能 | 量化 |
| 时值 | 部分能 | 必须落在网格上，靠 `0` 截断 |
| 和弦 | 能 | `(135)`，括号内同时发声 |
| 多声部 | 能 | 连续几行 = 同时响的多个声部 |
| 每音力度 | **不能** | 只有全局 `Vel = 90 +-10` |
| 音色 / 通道 | **不能** | 导出永远 Program 0 |
| 延音踏板 | **不能** | 可选择性并进时值 |
| 速度变化 | **不能** | 只取一个 bpm，变化大就警告 |
| 三连音 / 5 连音 | **不能** | 量化到最近 2 的幂位置，警告 |
| 拍号 6/8、12/8、5/4… | 部分 | 见 4.2 的映射表 |
| 调式 | 只有大调（根音可带 `#`） | 小调按关系大调写，主音变 `6` |
| 连奏 `legato()` | 能 | v1 不用；v2 可作为"减少 `0` 的压缩手段" |

## 3. 总体数据流

```text
.mid 文件
   |  MidiFileReader            解析 SMF（format 0/1/2、running status、meta）
   v
RawMidi（tracks / notes / tempo / 拍号 / 调号 / CC64 / 通道）
   |  MidiNormalizer            统一 PPQ=480、套用拍号映射、可选踏板延音、修剪重叠同音
   v
NormalizedMidi（绝对 tick、单拍号、单 bpm）
   |  KeyDetector               12 个调里挑最贴合的大调 + 音级换算
   v
PitchedNotes（音高 + 音级 + 升降号 + 八度偏移）
   |  VoiceSplitter             按"同时开始必须同时结束"拆声部（贪心区间着色）
   v
Voice[]（每声部一串 NoteUnit）
   |  AttmTextBuilder           逐小节挑段数 S、逐段挑单元数 U、生成文本（含 $/% 前缀优化）
   v
.attm 文本
   |  AttmParser                回读校验（必须 0 诊断、音符集合一致）
   v
预览 / 导入到编辑器
```

新增文件（预计）：

```text
Core/Midi/MidiFileReader.cs      SMF 读取（250 行左右）
Core/Midi/MidiEvents.cs          RawMidi / MidiTrackNote / TempoMap 数据模型
Core/Import/MidiImportOptions.cs 导入选项（UI 与转换器共用）
Core/Import/MidiNormalizer.cs    单位换算、拍号映射、踏板、重叠修剪
Core/Import/KeyDetector.cs       调性检测 + 音级换算
Core/Import/VoiceSplitter.cs     声部分解
Core/Import/AttmTextBuilder.cs   文本生成（核心，最费脑）
Core/Import/MidiImporter.cs      门面：文件 -> 文本 + 报告
Core/Import/ImportReport.cs      警告 / 统计
Views/ImportMidiWindow.xaml(.cs) 导入对话框
```

## 4. 核心算法

### 4.1 读 MIDI

要处理的情况，按踩坑概率排序：

```text
1. running status（省略状态字节）—— 不少旧文件这么写
2. note on + velocity 0 当 note off —— 必须支持
3. 同音高重复按下的"叠音" —— 用栈配对，配对不上的收尾时补 note off
4. format 1 多轨 —— 合并成一条时间轴（同一通道按轨分开统计）
5. PPQ 各异（96 / 384 / 960）—— 统一缩放到 480：tick * 480 / filePPQ
6. SMPTE 时基（division 高位为负）—— 罕见，直接拒绝并提示
7. tempo 变化（meta 0x51）—— 记下来，只取"时长占比最大"的那个 bpm
8. 拍号（0x58）、调号（0x59）—— 读出来当默认值，允许用户覆盖
9. 打击乐通道 10（index 9）—— 默认整条丢掉
10. program change / 控制器 —— 只记录，不进文本
11. 文件截断 / 长度字段错 —— 报"文件损坏"，不抛异常给 UI
```

### 4.2 拍号映射（v1 建议）

| MIDI 拍号 | 处理 |
| --- | --- |
| 4/4 | 直接支持 |
| 3/4 | 直接支持 |
| 2/4 | 两小节并成一节 4/4（音符位置天然对齐，只是小节线换位置） |
| 2/2 | 视为 4/4（一小节 = 4 个四分音符，长度相同） |
| 6/8 | 视为 3/4，用十六分网格（6 个八分 = 12 个十六分，每个八分正好 2 格，**完全精确**） |
| 12/8 | 同上思路但一小节 = 24 个十六分，超出 4/4 的 16 格 → 拒绝或只导前几小节 |
| 5/4、7/8、9/8… | 拒绝，提示"ATTM 只能写 4/4 和 3/4"，并给建议（先用别的软件换成 4/4 再导） |

拒绝时不要让用户白等：对话框里直接说明原因，不生成半成品。

### 4.3 量化

```text
目标：给一个小节，找一个"网格"能精确覆盖本声部所有音的起点和终点

1. 取本小节的起点集合 P = {所有音的 start} ∪ {所有音的 end}
2. 对候选段数 S ∈ {1,2,4}（4/4）或 {1,2,3,4}（3/4）：
     对每段 s：
          segLen = 小节长度 / S
          取落在本段的相对位置 p（0 <= p < segLen）
          U = segLen / gcd(segLen, 所有 p)          # 最小可行单元数
          U = 向上取到 2 的幂（理论上 gcd 已保证，兜底）
          若 U > 32 或 p 不能被 segLen/U 整除 -> 这个 S 不可行
      代价 = ΣU + 0 的数量 + 5 * 跨段重音数        # 越小越干净
3. 选代价最小的 S；都不行就退到"最粗可行网格 + 量化偏差"，并计入报告
```

量化偏差 = 每个音被挪动的最大 tick 数，换算成毫秒显示给用户
（例如"最大 18 ms"）。超过 1/8 拍（60 ms @120bpm）的音单独列出来。

### 4.4 声部分解

ATTM 一行里**同时开始的音必须同时结束**（否则时值不同没法写），所以：

```text
1. 把音按 (start, end) 分组，同 start 同 end 的一组 = 一个"单元"（和弦）
2. 按 start 排序，贪心区间着色：
      候选声部 = 上一个单元 end <= 本单元 start 的
      在这些里挑"上一个音高离本单元平均音高最近"的（减少声部交叉）
      没有候选就开新声部
3. 声部数 > 上限（默认 3）时：
      先把能合的相邻声部合掉（合并后不冲突才合）
      还超就把音数最少的声部的音丢掉，计入报告
```

贪心区间着色在"拆声部"这件事上是最优解（区间图着色 = 最大重叠深度），
所以声部数不会比理论最小值更多。

### 4.5 调性检测与音级换算

ATTM 只有自然大调，所以"选哪个大调当 `1`"决定了整篇谱子好不好读。

```text
1. 统计 12 个音级的"总时长"（不是音数，长音权重更大）
2. 对 12 个候选根音，算"落在该大调音阶内的时长占比"，加上首尾音加权
3. 得分最高的那个就是 1 = X
4. 小调会自动落到关系大调上（A 小调 -> 1 = C，主音写成 6），这正好是简谱惯例
5. 音级换算：pitch -> 半音差 -> 大调音阶里的度数 + 是否需要 #
   大调音阶 = 0 2 4 5 7 9 11，12 个音级都能写成"度数 + 可选 #"
```

升降号落地规则：

```text
差 0,2,4,5,7,9,11  -> 度数 1..7，不加 #
差 1,3,6,8,10      -> 度数的下方那个音 + #（如 C 调里 Eb 写成 #2）
```

### 4.6 行八度前缀优化

`1` 固定在中央 C（MIDI 60）。流行旋律大多在 60-84，
不处理的话满屏 `+`。所以每行算一次：

```text
shift = clamp(round((本行音高中位数 - 60) / 12), -2, 2)
shift > 0  -> 行首写 shift 个 '$'
shift < 0  -> 行首写 -shift 个 '%'
写完后每个音再按 (音高 - 60 - shift*12) 算度数和 +/-   # 通常就不需要 + 了
```

### 4.7 文本生成

```text
bpm = <取整或一位小数>
1 = <根音> 4/4
Vel = <中位力度> +-0

<第 1 小节 声部 1>
<第 1 小节 声部 2>          # 有多声部才是连续多行

<第 2 小节 声部 1>
...
```

单声部时每小节一行，小节之间一个空行。

小节的每一段内：

```text
对单元 k = 0..U-1：
    如果该位置有音开始 -> 写音符（多个音写 (135)，带 +/- 和 #）
    否则              -> 写 0
段与段之间用逗号
```

### 4.8 时值怎么落到格子上（v0.3.0 定稿：一个音只写一次）

简谱里**一格 = 一个音 = 一格的时间**，而且一格不能跨过逗号（段线）。所以"时值"只能靠
格子的疏密 + `legato()` 来凑。定稿的规矩是：

```text
1. 一个音只写一次，绝不把同一个音重写一遍去凑时值 —— 这样导出的 MIDI 里
   每个音头都能和原曲对上，不会无中生有多出来的起音
2. 每个音挑"一格"：一格的长度 = 这一段的步长 = segLen / 2^j（j = 0..5）
   条件：步长能整除这个音在段内的位置、不超过"到下一个音的距离"、也装得进这一段
   在满足条件的步长里挑最接近原时值的那个
3. 同一小段里步长不同的音没法写成一行（一行里一格的时值必须统一），各占一行
4. 一直响到段末的一组音，可以用 legato(...) 铺满这一段（唯一能"延长时值"的语法）
5. 时值本身写不出来时（附点、三连音、跨段的音），只能就近取一格：
   音会变短/变长一点，报告里数出来
```

代价要说清楚：简谱的步长只能是 `segLen / 2^j`，而 MIDI 里的时值可以是任意比例
（比如附点八分 = 3/16 拍）。加上"一格不能跨段"这条，像"从 3/16 拍处起音、一直响两拍"
这样的音**在 ATTM 里根本写不出来**：它最多只能占一小格（1/8 拍）。
旧版本的做法是把它在每一拍上重新起一次音来保住时值，代价是谱面上同一个音被敲好几遍；
现在按"一个音只写一次"处理，宁可短一点也不重复起音。

小节线是唯一例外：尾巴极短的音直接收掉；尾巴很长的音如果也收掉，整段延音就消失了，
这时才在下一个小节重新起音（报告里单独列出来）。

## 5. 走一遍完整例子

假设 MIDI（4/4，120bpm，单轨）里第 1 小节是：

```text
C4 八分, D4 八分, E4 四分, 休止四分, C4+E4+G4 全音符（跨到第 2 小节）
```

第 1、2 拍需要两个八分音符，第 3、4 拍只是休止 + 和弦起点，第 5 个音要跨小节。
只有前两拍需要细分，所以 S=4（每拍一段）代价最小：

```text
12,3,0,0        ->  C4 D4 | E4 | 休止 | 休止
```

注意第 2 拍只写 `3`：段内 1 个单元就等于 1 拍，E4 自然撑满这一拍 ✓

第 2 小节的和弦：

```text
(135)
```

再叠一个高八度的旋律声部（同一小节连续两行）：

```text
$ 5,5,6,5
(135)
```

`$` 让上面那行整体高八度，所以不用每个音写 `+5`。

## 6. 自检环：生成完必须能读回来

生成文本后立刻用 `AttmParser` 解析一遍，然后比对：

```text
1. Diagnostics 必须为空（不为空说明生成器有 bug，直接报错而不是给用户坏文件）
2. 解析出的音符集合 == 量化后的目标音符集合
   （音高完全相同；起止时间允许 0 tick 误差，因为我们是精确对齐的）
3. 小节数 == 目标小节数
```

这一步既是运行时保险，也是最好的测试手段（见第 9 节）。

## 7. UI 设计

### 7.1 入口

```text
工具栏：piano 图标左边加一个导入按钮，用 upload_file（U+E9FC）
       ToolTip：导入 MIDI（.mid / .midi）
拖放：  窗口已经 AllowDrop，现有逻辑只认 .attm/.txt
       扩展成：.mid/.midi -> 走导入流程
```

导入是"生成新内容"，会覆盖当前文档，所以先 `ConfirmDiscard()`（现有逻辑）。

### 7.2 导入对话框

沿用 `SettingsWindow` 的风格（直角、主题色、Material 图标）：

```text
[文件]     欢乐颂.mid                                    选择…
[检测到]   format 1 · 2 轨 · 4/4 · 120bpm · 1 = G · 128 音 · 24 小节

[拍号]     ( ) 自动 4/4    ( ) 3/4        # 只在无法自动判定时可选
[调]       ( ) 自动      1 = [ G ] [-]    # 下拉 12 个键（含 #）
[量化]     ( ) 自动      ( ) 1/8  ( ) 1/16
[声部]     上限 [ 3 ]    [x] 只导入最上面的旋律
[其它]     [x] 跳过打击乐通道   [ ] 把延音踏板算进时值
           [x] 修剪重叠的同音

[预览]     前 8 行的文本，Lekton 字体，灰底
[警告]     三连音 12 处已量化到最近位置；声部 4 已丢弃 6 个音；速度在 0:42 处变化
                                   [ 取消 ]  [ 导入 ]
```

对话框里所有选项都是"改了立刻重算预览"，转换本身很快（几十毫秒），不需要进度条。
文件很大（>10 分钟 / >2000 小节）时给个进度条 + 取消。

### 7.3 导入后的落点

三个可选（需要你拍板，见第 11 节）：

```text
A. 替换当前文档（先问要不要保存），标题变「未命名.attm」
B. 插入到光标处
C. 直接另存成 <原名>.attm 到谱库目录，然后打开它
```

我倾向 **A**，理由：MIDI 导入的结果是一整篇新谱子，插到光标处几乎没有意义；
而"另存到谱库"会让谱库变成垃圾场。

导入完在状态栏给一次性提示：

```text
已导入 128 个音 · 24 小节 · 2 个声部 · 最大量化偏差 18 ms（点这里看详情）
```

### 7.4 拖放

```text
.mid / .midi  ->  打开导入对话框（文件名自动填好）
.attm / .txt  ->  原来的打开文件逻辑
其他          ->  忽略
```

## 9. 测试计划

### 9.1 单元测试（ATTM.Tests，纯逻辑）

```text
读取器
  - 自造的 format 0 / format 1 文件（用现有 MidiFileWriter 写，再读回来）
  - running status、note on velocity 0、同音叠音、截断文件
  - PPQ 96 / 384 / 960 -> 统一到 480 的换算
  - tempo / 拍号 / 调号 meta 解析

量化与生成
  - 表驱动：给定"音符列表 + 期望文本"，比对字符串
  - 4/4 与 3/4 各自的最优 S 选择
  - 长音 + 细碎音符混在同一声部时的取舍与警告
  - 3 连音输入 -> 量化到最近 16 分位并报警告
  - 6/8 -> 3/4 精确映射（每个八分落在 2 个十六分格上）

声部与调性
  - 三个音重叠 -> 必出三声部；顺序不重叠 -> 单声部
  - C 大调 / G 大调 / A 小调（期望 1 = C）/ 带降号的旋律（期望出现 #）
  - 声部上限截断后报告音数正确

回读校验
  - 生成 -> AttmParser 解析 -> 音符集合完全一致（这条对所有用例都跑）
```

### 9.2 回环测试（最有价值的一条）

```text
samples/欢乐颂 - 演示谱.attm
   -> 导出 MIDI
   -> 导入 MIDI
   -> 生成的文本再解析
   -> 与原始 Score 的音高集合、每小节音符数比对

允许的差异：量化网格导致的时值差（欢乐颂全是四分八分，应该 0 差异）
```

这条能一次性验证"读 + 量化 + 生成 + 校验"整条链路。

- 工具栏有导入按钮（图标 U+E9FC）

  诊断数为 0、音符数 > 0、缩略图有条目
- 拖放白名单：.mid 能被识别，.png 不能

## 11. 定稿的取舍（原"待拍板"）

最终按下面这套做的，所以界面上**没有任何导入对话框**，点按钮/拖文件就直接转：

```text
导入落点      A：替换当前文档（先问要不要保存），标题变 <原 MIDI 名>.attm
拍号          能映射就映射，映射不了直接拒绝并说明
声部          全声部；重叠的音各占一行，不用 () 和弦语法
延音          踏板算进时值；铺满一段且等距的音型用 legato() 表达
新起音        同一个音只写一次；时值不够就用"格子 + legato"凑，实在凑不出来
              才截短（报告里会数"有 N 个音被截短"），不会把音重写一遍
打击乐        丢弃
速度          只取占时最长的那个 bpm
界面          不加对话框（选项都在 MidiImportOptions 里，先给默认值）
```

下面是当初的候选清单，留档用：



1. **导入落点**：替换当前文档（A）/ 插入光标（B）/ 另存并打开（C）？我建议 A。
2. **拍号不支持的曲子**：直接拒绝并说明，还是尽力映射（2/4 合并、6/8 当 3/4）？我建议"能映射的映射，剩下的拒绝"。
3. **默认导单声部还是全声部**：钢琴曲全声部会有 2-4 行，谱面挺花；"只导入旋律"作为默认勾选更实用，但会丢掉伴奏。
4. **声部上限**默认 3 够吗？（多声部时行数 = 声部数 × 小节数，太长也会烦）
5. **打击乐通道**默认丢弃，对吗？
6. **延音踏板**默认不算进时值（更接近乐谱原貌），还是算进去（更接近听感）？
7. **速度变化**的曲子：只取主 bpm + 警告，可以接受吗？
8. 要不要顺手做一个**命令行入口**方便批量转：
   `ATTM.exe --import-midi input.mid output.attm`（也方便我自己写回环测试）
9. ~~需不需要"保持音拆声部"开关？~~ 已经默认这么做了：写不顺的音会自动拆到单独一行。

## 12. 风险与兜底

| 风险 | 兜底 |
| --- | --- |
| 复杂钢琴曲导出后一堆 `0`、可读性差 | 默认"只导入旋律"；提供 S 枚举 + 代价函数；实在不行就报告里建议换个量化精度 |
| 三连音、自由节奏 | 量化 + 明确警告，不假装精确 |
| 生成器 bug 生成非法文本 | 强制回读校验，失败就报"内部错误"并输出诊断信息，绝不写进编辑器 |
| 大文件卡界面 | 转换放在 `Task.Run`，进度回调 + 可取消 |
| 用户以为能"完美还原" | 对话框里就把限制写清楚（力度/音色/三连音会丢） |
