# 06 · 配置与主题

> 两件事：用户配置落在哪、有哪些字段；界面颜色从哪来、怎么换。
>
> 相关源码：`Services/AppConfig.cs`、`Services/ThemeService.cs`、`Services/WindowTheme.cs`、`Themes/*.xaml`、`Editing/EditorPalette.cs`。

---

## 1. 配置文件

**位置**：`%APPDATA%\ATTM\config.json`（= `AppConfig.ConfigPath`）

**格式**：JSON，缩进，`UnsafeRelaxedJsonEscaping`（中文不转义）。

```json
{
  "Version": 3,
  "Theme": "Dark",
  "MidiOutputDevice": "",
  "DefaultSaveFolder": "C:\\Users\\你\\Music\\ATTM",
  "EditorFontSize": 18,
  "AutoScrollOnPlay": true,
  "PhrasePreviewVisible": false,
  "WindowLeft": 300,
  "WindowTop": 180,
  "WindowWidth": 1100,
  "WindowHeight": 720,
  "WindowMaximized": false
}
```

### 1.1 字段表

| 字段 | 类型 | 默认 | 说明 | 由谁写 |
| --- | --- | --- | --- | --- |
| `Version` | int | 3 | 迁移版本号 | `Load` 自动 |
| `Theme` | string | `Dark` | `Dark` / `Light` / `System` | 主题按钮、设置窗口 |
| `MidiOutputDevice` | string | 空 | 设备名；空 = 自动（优先包含 `GS Wavetable` 的设备） | 设置窗口 |
| `DefaultSaveFolder` | string | 空 | 上次保存目录；空 = `音乐\ATTM` | 每次保存后 |
| `EditorFontSize` | double | 18 | 9–40，`Ctrl+滚轮` 也可改（但不落盘，只有设置窗口/启动时读） | 启动时读 |
| `AutoScrollOnPlay` | bool | true | 播放时把当前行滚进视野 | 默认值 |
| `PhrasePreviewVisible` | bool | false | 乐句预览侧边栏展开状态 | 工具栏 ToggleButton |
| `WindowLeft/Top/Width/Height` | int? | null | 窗口位置，首次运行为空 → 居中 | 关闭窗口时 |
| `WindowMaximized` | bool | false | 是否最大化 | 关闭窗口时 |

### 1.1.1 主路径不可写时的退路

`%APPDATA%\ATTM` 在某些受限环境（公司策略、漫游配置损坏、沙箱）里**只能建目录、不能写文件**，
写入会抛 `UnauthorizedAccessException`。以前这个异常被 `catch { }` 吞掉，表现为「改了什么设置重启全没了」。

现在 `AppConfig.Save()` 会依次尝试：

```text
1. %APPDATA%\ATTM\config.json        主路径
2. <ATTM.exe 所在目录>\ATTM.config.json   退路（便携模式）
```

- 返回 `bool`：两个位置都写不了才返回 `false`，原因在 `AppConfig.LastSaveError`；
- 实际使用的路径在 `AppConfig.ActiveConfigPath`（插件管理器的摘要行会显示它）；
- 插件管理器切换启用状态后如果保存失败，会弹窗告知，而不是假装成功；
- 错误日志同样有回退：`%APPDATA%\ATTM\last-error.log` → `<exe目录>\last-error.log`。

### 1.2 迁移规则

```csharp
if (config.Version < 2 && Math.Abs(config.EditorFontSize - 15) < 0.01) config.EditorFontSize = 18;
if (config.Version < 3) { config.Version = 3; config.Save(); }
```

- v1 → v2：旧默认字号 15 太小，升到 18。
- v2 → v3：去掉自定义主题色，开始记忆窗口位置。

### 1.3 容错

`Load()` 与 `Save()` **全部 catch 并静默**：配置文件损坏、目录无写权限，都退回默认值继续运行。这是刻意的——小工具不应因为配置问题打不开。

## 2. 两个固定目录

| 目录 | 定义 | 用途 |
| --- | --- | --- |
| **谱库** | `音乐\ATTM`（`AppConfig.LibraryFolder`，不存在则 `Directory.CreateDirectory`） | `Ctrl+O` / 工具栏「打开」永远打开这里；安装包也把示例谱子装到这里 |
| **保存目录** | `DefaultSaveFolder`，空则回退谱库（`ResolveSaveFolder`） | 保存对话框的初始目录 |

> 谱库是**固定**的，不跟随「上次保存到哪」。这条规则来自一次实测反馈：跟着上次目录跑会让用户找不到谱子。

## 3. 主题体系

### 3.1 三种模式

```csharp
public enum AppTheme { Dark, Light, System }
```

| 模式 | 行为 |
| --- | --- |
| `Dark` | 固定深色 |
| `Light` | 固定浅色 |
| `System` | 读注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize\AppsUseLightTheme`（非 0 = 浅色）；并监听 `SystemEvents.UserPreferenceChanged`（`General` / `Color`）实时跟随 |

工具栏的主题按钮只在 **深色 ↔ 浅色** 之间切换（点一下就变，不需要打开设置）；`跟随系统` 只能在设置窗口里选。

### 3.2 资源字典结构

```text
App.xaml 的 MergedDictionaries：
  Themes/Typography.xaml      字体与字号（不随主题变）
  Themes/Palette.Dark.xaml    调色板（初始值）
  Themes/Controls.xaml        控件样式（全部用 DynamicResource）
```

切换主题时 `ThemeService.ApplyPalette()` **原地替换** `Source` 含 `"Palette."` 的那一项字典，然后抛 `ThemeChanged`；所有界面通过 `DynamicResource` 自动跟随。

### 3.3 字体与字号（`Themes/Typography.xaml`）

| 键 | 值 | 用途 |
| --- | --- | --- |
| `Font.UI` | `Microsoft YaHei UI, Segoe UI, Arial` | 界面文字 |
| `Font.Editor` | pack URI → `#Lekton, Consolas, Courier New` | 编辑器（等宽） |
| `Font.Icon` | pack URI → `#Material Symbols Sharp, Segoe UI Symbol` | 工具栏图标 |
| `Size.UI` | 13 | 界面字号 |
| `Size.UI.Small` | 11.5 | 状态栏 |
| `Size.Editor` | 15 | 编辑器初始字号（实际由 `AppConfig.EditorFontSize` 覆盖为 18） |
| `Size.Icon` / `Size.Icon.Small` | 20 / 16 | 图标尺寸 |

## 7. 窗口位置记忆

```csharp
// 关闭时
bounds = WindowState == Normal ? new Rect(Left, Top, ActualWidth, ActualHeight) : RestoreBounds;
if (bounds.Width < MinWidth || bounds.Height < MinHeight) return;   // 不合理就不存

// 启动时
if (!bounds.IntersectsWith(虚拟屏幕矩形)) return;                   // 上次的显示器可能已拔掉
```

展开乐句预览时 `EnsurePhraseRoom` 会把 `MinWidth` 从 720 提到 1180，收起时回落。

## 8. 改外观的步骤

1. **改颜色** → 只动 `Themes/Palette.Dark.xaml` 与 `Palette.Light.xaml`，两边键必须一一对应（`EditorPalette.FromResources` 按同名键取值，缺键会静默用硬编码回退，容易漏改）。
2. **加新语法类别配色** → 两个 Palette + `EditorTokenClass` + `EditorHighlighter.Classify` + `EditorPalette`（字段 + `BrushFor`）。
3. **改控件外观** → `Themes/Controls.xaml`，保持 `DynamicResource`。
4. **改完跑** `dotnet run --project tests/ATTM.UiChecks`：它会断言深/浅两种底色与强调色的**具体色值**，改色不改测试会红（这是有意的，防止手滑）。
