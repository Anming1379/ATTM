## 1. 编码约定（仓库既有纪律）

摘自 `PLAN.md` 第 15 节，实际提交都遵守这些：

| 约定 | 说明 |
| --- | --- |
| 文件编码 | C# / XAML 用 **UTF-8**；`.ps1` 必须 **UTF-8 with BOM**（PowerShell 5.1 按 ANSI 读无 BOM 的文件会把中文弄坏）；`.cmd` 纯 ASCII |
| XAML 注释 | 禁止出现 `--`（XML 注释不合法） |
| 文案语言 | 所有 UI 文本、诊断消息、文档 = **中文**；代码标识符 = **英文** |
| 资源引用 | 颜色/尺寸一律 `DynamicResource`，View 里禁止硬编码（`EditorPalette` 的硬编码只允许出现在回退值里） |
| 解析器 | **纯函数式**：`string → ParseResult`，无静态可变状态，可直接测 |
| 提交粒度 | 按里程碑；每个里程碑结束必须 `dotnet build` + 两套测试全绿 + 程序可运行 |
| 解决方案文件 | 根目录**不放 `.sln`**；`dotnet build` 直接构建 `ATTM.csproj` |

## 2. 常见扩展任务

### 2.1 新增一条语法（以「附点」为例的完整清单）

| 步骤 | 文件 | 内容 |
| --- | --- | --- |
| 1 | `Core/Syntax/TokenKind.cs` | 若需要新符号，加枚举值 |
| 2 | `Core/Syntax/AttmLexer.cs` | 识别该符号并产出 token |
| 3 | `Core/Syntax/AttmParser.cs` | 在 `TryParseNote` / `ParseSegment` 里解释它 |
| 4 | `Core/Syntax/DiagnosticCode.cs` | 追加新错误码（**只追加，不改已有数值**） |
| 5 | `Editing/EditorHighlighter.cs` | `Classify` 里给新 token 一个类别（否则它会是 `Unknown` → 标红） |
| 6 | `Editing/EditorPalette.cs` + `Themes/Palette.*.xaml` | 若需要独立颜色，加 Brush 键与映射 |
| 7 | `docs/02-语法参考.md` | 更新规则与诊断码表 |
| 8 | `ATTM 语法教程.md` | 面向用户的说明与示例 |
| 9 | `tests/ATTM.Tests/Program.cs` | 加 `Check(...)`；**教程里的新示例必须能被解析**，否则第 2.13 组测试会红 |
| 10 | `PLAN.md` | 记一行改动与理由 |

### 2.2 新增一条指令

1. `AttmParser.IsDirectiveLine` 里加上名字（目前只认 `bpm` / `vel` 与 `1 = …`）。
2. `ParseDirective` 里分派到新的 `ParseXxxDirective`。
3. 指令必须遵守现有两条铁律：**必须在所有小节之前**、**只能声明一次**。
4. 新字段加到 `Score`，并在 `Parser.Run` 组装 `Score` 时赋值。
5. 语法高亮无需改：指令行是按「含等号」判定的，新指令自动继承 `Directive` 配色。

### 2.3 新增诊断消息

```csharp
// 1) DiagnosticCode.cs —— 追加，不插队
NewRuleViolation = 125,

// 2) 解析处
AddDiagnostic(DiagnosticCode.NewRuleViolation, token, token.Span, "中文说明，带示例");

// 3) docs/02-语法参考.md 第 13 节表格加一行
```

诊断消息的惯例：**说清「哪里错」+ 给一个正确写法示例**，例如 `八度前缀 $ / % 后面必须跟一个空格，例如 "$ 1,2,3,4"`。

### 2.4 新增主题令牌

1. `Themes/Palette.Dark.xaml` 与 `Palette.Light.xaml` **同时**加同名键（漏一边会静默用回退色）。
2. 使用处写 `{DynamicResource Brush.YourKey}`。
3. 若编辑器要用，追加到 `EditorPalette`（字段 + `FromResources` + `BrushFor`）。
4. 跑 `ATTM.UiChecks`：它断言了若干具体色值，能挡住手滑。

### 2.5 新增一个编辑器按键

在 `EditorTextView.OnPreviewKeyDown` 里加分支，并：

1. 设置 `e.Handled = true`（否则会继续冒泡到 `MainWindow`）。
2. 任何修改文本的分支必须走 `ApplyEdit(...)`，这样才能进入撤销栈并触发 `BufferChanged`。
3. 改完记得在 `docs/04-编辑器实现.md` 的按键表里补一行，并在 `ATTM 语法教程.md` 的快捷键节同步。

### 2.6 新增一个工具栏按钮

1. `MainWindow.xaml` 里加 `Button`（用 `IconButton` 样式，`Content` 填 Material Symbols 码位）。
2. `MainWindow.xaml.cs` 加 Click 处理。
3. 若涉及启停，在 `UpdateButtons()` 里同步 `IsEnabled`。
4. 图标码位可以在 Google Fonts 的 Material Symbols 页面查到，写成 `&#xEXXX;`。

### 2.7 新增一条测试

往对应 harness 里加一行 `Check("中文断言名", () => ...)`。

- 纯逻辑 → `tests/ATTM.Tests/Program.cs`。
- 涉及控件/渲染 → `tests/ATTM.UiChecks/Program.cs`（那里已经有创建窗口、找元素、取样像素的工具函数）。
- 播放时序 → `tests/ATTM.Tests/PlaybackChecks.cs`（有假时钟与记录型输出）。

## 3. 调试技巧

### 3.1 把任意谱面导出成 .mid

```bash
dotnet run --project tests/ATTM.Tests -- --export 某谱.attm 输出.mid
```

不用开界面就能验证 MIDI 写入结果。

### 3.2 把界面渲染成 PNG

```bash
dotnet run --project tests/ATTM.UiChecks -- --dump out.png
```

这是本项目**推荐的视觉验收方式**：本机截图工具在这个环境下不可靠，进程内 `RenderTargetBitmap` 才准。

### 3.3 看解析结果

最快的办法是在 `ATTM.Tests` 里临时加一行 `Check` 打印，或直接用 `--export` 看导出的 MIDI 是否符合预期。

### 3.4 判断「没有声音」是设备问题还是代码问题

- 状态栏显示「就绪（无 MIDI 设备）」或「（静音）」→ 设备层问题。
- 有高亮但无声 → 检查 `ScorePlayer.Output.IsOpen` 与 winmm 返回码。
- 设置窗口里点「刷新」看能不能枚举到设备。

## 4. 容易踩的坑（都有历史教训）

| 坑 | 后果 | 正确做法 |
| --- | --- | --- |
| 改了 `FormattedText` 但没清 `_lineCache` | 显示旧颜色/旧内容 | `ApplyEdit` / `SetParse` / `SetPalette` 都会清；新增入口也要清 |
| 用 WPF 动画时钟做动画 | 离屏/无头环境动画不推进，测试挂死 | 用 `DispatcherTimer` 自驱动（`AnimatePhraseWidth` 就是这么写的） |
| 缩略图各处各算一套坐标 | 条与视野框错位 | 全部走 `_linePixel` + `YForLine` 统一映射 |
| 字体 pack URI 写错 | 图标显示豆腐块，等宽字体回退 Consolas | 字体必须在 `assets/fonts/`，URI 为 `pack://application:,,,/ATTM;component/assets/fonts/#字体族名` |
| PowerShell 脚本存成 UTF-8 无 BOM | PS 5.1 按 ANSI 解析，中文直接语法错 | 存成 UTF-8 **with BOM** |
| 主题参数取反 | 深色配置显示浅色 | 统一走 `ThemeService.SetMode(config.Mode)`，不要自己判断布尔 |
| 在 `OnRender` 里建 `FormattedText` 做排版 | 掉帧 | 排版只做一次（`PhraseLayout.Build`），帧内只 `PushTransform` + `DrawText` |
| 播放时每帧刷状态栏 | 无谓重绘 | `_lastSecond` 秒级去重 |
| 新增诊断码时改动已有数值 | 文档与测试全错位 | 只追加，不插队 |

## 6. 文档维护规则

`docs/` 下的 10 个文件是**活文档**，改代码时同步维护：

| 改动类型 | 需要更新的文档 |
| --- | --- |
| 语法 / 诊断码 | `02-语法参考.md`（规则 + 码表）、`ATTM 语法教程.md` |
| 新增类型或公开成员 | `03-模块API参考.md` |
| 编辑器行为 | `04-编辑器实现.md` |
| MIDI / 播放 | `05-播放与MIDI.md` |
| 配置字段 / 主题令牌 | `06-配置与主题.md` |
| 构建脚本 / 安装包 | `07-构建与发布.md` |
| 测试用例 | `08-测试体系.md` |

README 里的「文档」小节列出了用户可见的那几份（语法教程、README、许可、AI 说明、PLAN）；`docs/` 是面向开发者的技术文档集。
