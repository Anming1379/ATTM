# 12 · 插件系统

> ATTM 从 0.3 起把「导入 / 导出 / 命令 / 界面」都做成了扩展点。
> 本文是插件作者与宿主维护者共用的说明书：能做什么、怎么接、边界在哪。

---

## 1. 一句话

**程序目录 `plugins\` 下的每个 dll 都会被扫描；实现了 `IAttmPlugin` 的类在启动时被实例化并初始化，它声明的能力（导入 / 导出 / 命令 / 控件）由界面按需取用。**

| 能力 | 接口 | 效果 |
| --- | --- | --- |
| 导入 | `IImporterPlugin` | 认领扩展名，拖放 / 粘贴 / 命令行 / 对话框都能走它 |
| 导出 | `IExporterPlugin` | 出现在「导出」对话框的文件类型里 |
| 命令 | `ICommandPlugin` | 工具栏多出按钮，可带图标与启用条件 |
| 控件 | `IUiPlugin` | 往工具栏 / 状态栏 / 设置页插入**任意 WPF 控件** |

内置插件：`attm.midi-import`（MIDI → 简谱），源码在 `plugins/ATTM.Plugin.MidiImport/`。删掉 `plugins` 目录，程序照常启动，只是这些入口消失。

## 2. 目录、装载与禁用

| 顺序 | 目录 | 用途 |
| --- | --- | --- |
| 1 | `<ATTM.exe 所在目录>\plugins` | 随程序分发 |
| 2 | `%APPDATA%\ATTM\plugins` | 用户自装，升级不覆盖 |

规则：

- 只扫描目录**顶层** `*.dll`，不递归。
- 同一个 `Id` 只装载一次，先装的赢。
- 读取类型失败的 dll（原生依赖等）静默跳过。
- **被禁用的 dll 直接跳过，不执行其中任何代码**——禁用列表存的是文件名，写在 `%APPDATA%\ATTM\config.json` 的 `DisabledPlugins`。
- 沙箱是默认：装载前先做 **API 静态体检**（见 §15），引用了禁止 API 又没申请授权的插件会被拒装。
- 用户确认过无沙箱权限的插件记在 `ApprovedPlugins`（`id@version`）。
- 目录不存在不算错误。

## 3. 生命周期

```text
启动
  └─ 扫描目录 → 每个 dll 一个 AssemblyLoadContext
       ├─ 被禁用？→ 记一条 Disabled，不加载
       └─ 找到 IAttmPlugin → 实例化 → Initialize(IPluginContext)
            失败就记一条 Failed，不影响别人

启动后（主窗口构造末尾）
  └─ 读取 Command / UiItem 聚合结果 → 挂进工具栏、状态栏

运行期
  └─ 用户点击 → Execute(context) / Import(path) / Export(path)

退出
  └─ ShutdownAll() → 每个 Shutdown()
```

没有热重载：插件在进程内只加载一次，改动后重启生效。

## 4. 契约

命名空间 `ATTM.Plugins`，源码 `PluginApi/`，属于主程序（`ATTM.exe`）。

### 4.1 `IPluginContext` —— 插件能碰到的一切

```csharp
public interface IPluginContext
{
    string ApplicationDirectory { get; }   // ATTM.exe 所在目录（只读）
    string DataDirectory { get; }          // 本插件专属可写目录，已创建

    void Log(string message);

    string GetDocumentText();              // 当前编辑器全文
    void SetDocumentText(string text);     // 替换全文（会标记未保存并重新解析）
    void SetStatus(string message);        // 状态栏短期消息，6 秒后自动消失
    void ShowMessage(string message, bool isError = false);
}
```

**插件拿不到窗口、控件树、播放器**：需要读写文档就走这四个方法。这是「主程序不依赖插件、插件也不绑死主程序」的关键。

### 4.2 `IAttmPlugin` —— 入口

```csharp
public interface IAttmPlugin
{
    string Id { get; }
    string Name { get; }
    string Version { get; }
    string Description { get; }

    void Initialize(IPluginContext context);
    void Shutdown();
}
```

### 4.3 四种能力接口（全部可选，按需实现）

```csharp
public interface IImporterPlugin : IAttmPlugin
{
    IReadOnlyList<string> Extensions { get; }   // [".mid", ".midi"]
    string FileFilter { get; }                  // 对话框过滤串
    PluginImportResult Import(string path);
}

public interface IExporterPlugin : IAttmPlugin
{
    IReadOnlyList<string> Extensions { get; }
    string FileFilter { get; }
    void Export(IPluginContext context, string path);
}

public interface ICommandPlugin : IAttmPlugin
{
    IReadOnlyList<PluginCommand> Commands { get; }
}

public interface IUiPlugin : IAttmPlugin
{
    IReadOnlyList<PluginUiItem> UiItems { get; }
}
```

一个插件可以同时实现多个，例如「既导入又提供设置页控件」。

### 4.4 命令与控件

```csharp
public sealed record PluginCommand(
    string Id,
    string Title,
    string? ToolTip,
    string? IconGlyph,                       // Material Symbols 码位字符，如 "\uE87B"
    Action<IPluginContext> Execute,
    Func<IPluginContext, bool>? CanExecute = null);

public sealed record PluginUiItem(
    PluginUiSlot Slot,                       // Toolbar / StatusBar / SettingsPanel
    int Order,                               // 同槽位内排序，小的靠前
    Func<IPluginContext, FrameworkElement> CreateView);
```

`CreateView` 在 UI 线程调用**一次**并缓存；抛异常只会让这一项消失，不影响其它插件。

### 4.5 `PluginEntry` / `PluginState`

```csharp
public enum PluginState { Loaded, Failed, Disabled, PendingApproval }

public sealed class PluginEntry
{
    public IAttmPlugin? Plugin { get; }
    public string Source { get; }        // dll 文件名
    public string SourcePath { get; }
    public PluginState State { get; }
    public string? Error { get; }
    public IPluginContext? Context { get; }
    public bool IsLoaded { get; }
}
```

失败与被禁用的插件也留在列表里，插件管理器据此显示原因。

## 6. 插件管理器

工具栏最右边的拼图图标（`E87B`）打开。列出扫描到的全部插件：

| 列 | 含义 |
| --- | --- |
| 勾选框 | 启用 / 禁用（写进 `DisabledPlugins`，**重启生效**；待授权的条目不可勾选） |
| 名称 + 版本 | 来自 `IAttmPlugin` |
| 说明 | `Description` |
| 文件名 · 能力 | 例如 `ATTM.Plugin.MidiImport.dll · 导入` |
| 信任 | 沙箱 / 无沙箱（用户已授权） |
| 状态 | 已启用 / 已禁用 / 待授权 / 失败（原因红字显示） |

底部：**重新加载插件**（热重载，见 §16）、**打开插件目录**（两个目录都尝试打开）、**关闭**。禁用**不删除文件**，只是下次启动不加载；禁用表存文件名，换版本但文件名不变时禁用状态保持。

## 7. 宿主实现要点（`PluginHost`）

| 关注点 | 做法 | 为什么 |
| --- | --- | --- |
| 隔离 | 每个插件一个 `AssemblyLoadContext` | 各自带依赖，互不打架 |
| **类型身份** | `Load()` 对 `ATTM` 返回 `null`（回落默认上下文） | 否则插件里的 `IAttmPlugin` 不是同一个类型，`is` 永远为 false |
| 依赖解析 | `AssemblyDependencyResolver(插件路径)` | 插件目录旁的 dll 能找到 |
| 容错 | 装载 / 实例化 / 初始化 三层 try/catch | 一个坏插件不能让程序起不来 |
| 留痕 | 失败也进 `Entries` | 管理器里能看到「装了但没跑起来」 |
| 上下文 | 每个插件一个 `PluginContext`，数据目录按 Id 分开 | 插件互不干扰，日志带前缀 |
| 聚合 | `Importers` / `Exporters` / `Commands` / `UiItems` 只读快照 | 界面只读，不关心插件是谁 |

## 8. 写一个插件（带命令 + 状态栏控件的完整例子）

```text
plugins/ATTM.Plugin.Abc/
├── ATTM.Plugin.Abc.csproj
└── AbcPlugin.cs
```

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net10.0-windows</TargetFramework>
    <UseWPF>true</UseWPF>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
    <AssemblyName>ATTM.Plugin.Abc</AssemblyName>
    <OutputType>Library</OutputType>
    <EnableDynamicLoading>true</EnableDynamicLoading>
  </PropertyGroup>

  <ItemGroup>
    <ProjectReference Include="..\..\ATTM.csproj" />
  </ItemGroup>
</Project>
```

```csharp
using System.Windows;
using System.Windows.Controls;
using ATTM.Plugins;

namespace ATTM.Plugin.Abc;

public sealed class AbcPlugin : IImporterPlugin, ICommandPlugin, IUiPlugin
{
    private IPluginContext? _context;

    public string Id => "attm.abc";
    public string Name => "ABC 导入";
    public string Version => "1.0.0";
    public string Description => "把 ABC 记谱法转成简谱，并提供常用设置";

    // --- 导入 ---
    public IReadOnlyList<string> Extensions { get; } = new[] { ".abc" };
    public string FileFilter => "ABC 文件 (*.abc)|*.abc";

    public PluginImportResult Import(string path)
        => new(AbcToAttm.Convert(File.ReadAllText(path)), "导出.attm");

    // --- 命令 ---
    public IReadOnlyList<PluginCommand> Commands { get; }

    // --- 控件 ---
    public IReadOnlyList<PluginUiItem> UiItems { get; }

    public AbcPlugin()
    {
        Commands = new[]
        {
            new PluginCommand(
                "validate", "检查 ABC 语法", null, "\uE87B",
                static context => context.SetStatus("ABC 语法检查通过"),
                static context => context.GetDocumentText().Length > 0)
        };

        UiItems = new[]
        {
            new PluginUiItem(PluginUiSlot.StatusBar, 10, static _ =>
                new TextBlock { Text = "ABC", Opacity = 0.6, Margin = new Thickness(8, 0, 0, 0) }),

            new PluginUiItem(PluginUiSlot.SettingsPanel, 100, static context =>
            {
                var check = new CheckBox { Content = "导入时合并同音高" };
                check.Click += (_, _) => context.SetStatus(check.IsChecked == true ? "已开启合并" : "已关闭合并");
                return check;
            })
        };
    }

    public void Initialize(IPluginContext context) => _context = context;
    public void Shutdown() => _context = null;
}
```

构建 → 把 dll 放进 `plugins\` → 重启：

- 工具栏右侧出现「检查 ABC 语法」按钮（无文档时自动变灰）；
- 状态栏出现 `ABC` 标记；
- 设置窗口「插件」区多出这个勾选框；
- `.abc` 文件可以拖进来导入。

## 9. 架构约束：主程序不依赖插件

这条是硬约束，不是建议：

| 方向 | 允许 | 不允许 |
| --- | --- | --- |
| 主程序 → 插件 | 只认 `ATTM.Plugins` 契约与 `PluginHost` 聚合结果 | 引用任何 `ATTM.Plugin.*` 程序集、按类型名判断具体插件 |
| 插件 → 主程序 | 引用 `ATTM.exe` 拿契约；通过 `IPluginContext` 读改文档 | 直接 `new MainWindow`、访问控件、调用内部服务 |

**自动化守卫**：`tests/ATTM.Tests` 里有一条「主程序不引用任何插件程序集」，它反射 `MainWindow` 所在程序集的引用列表，出现 `ATTM.Plugin.*` 就红。删掉 `plugins\` 目录，程序必须照常启动——这条也由「被禁用的 dll 不装载」与「装载失败不影响宿主」两条测试兜着。

### 9.2 `attm.midi-ai`（内置小模型）

模型**跑在插件自己的进程里**：用 LLamaSharp（llama.cpp 的 .NET 绑定）直接加载 GGUF，
不需要 Ollama 之类的常驻服务。没有本地模型时才退回到「调用本机 HTTP 服务」。

```text
.mid ──MiniSmf──► 音符摘要（前 8 小节：音名:起点:时值）
                      │
                      ▼  提示词（ATTM 语法要点 + few-shot 示例）
              GGUF 模型（进程内，llama.cpp CPU 后端）
                      │
                      ▼  去代码块 → 只保留“像谱面”的行 → 缺指令就补
             AttmParser 校验 ──不合法/只有指令──► 带诊断重试 1 次 ──► 报错
                      │成功
                      ▼
                 编辑器里的 ATTM 文本
```

| 项 | 说明 |
| --- | --- |
| 扩展名 | `.mid` `.midi`（与基础插件重复，由导入对话框的过滤器选择） |
| 依赖 | `LLamaSharp` + `LLamaSharp.Backend.Cpu`（NuGet，随插件分发；win-x64 原生库约 9 MB） |
| 模型 | **自己放一个 `.gguf`**，在 设置 → 插件 → MIDI AI 整理 里指定路径 |
| 备用通道 | 模型路径留空时，用「服务地址 + 模型名」走 HTTP（Ollama /api/chat 或 OpenAI /v1/chat/completions） |
| 信任 | 实现 `ITrustRequestPlugin`：要读你指定的模型文件（并可能访问本机服务）→ 首次启动弹窗确认 |
| 输出治理 | 去 Markdown 代码块、丢弃解释性文字、补全 `bpm`/`1 =`/`Vel`、校验不通过自动重试一次 |

#### 实测数据（这台机器，CPU 推理）

| 模型 | 大小 | 加载 | 生成速度 | 8 小节输出 |
| --- | --- | --- | --- | --- |
| `gemma-3-4b-it Q4_K_M`（取自本机 Ollama blob） | 2.5 GB | ~25 s | ≈ 4 tok/s | 256 token 约 30 s，能产出合法谱面 |

> Ollama 的 blob 本身就是 GGUF（magic `GGUF`），把 `D:\AI\Ollama\Model\blobs\sha256-...` 直接填进「模型文件」就能复用，不必重新下载。

#### 选型建议

| 想要 | 建议 |
| --- | --- |
| 快 | 0.5B–1B 的 GGUF（`qwen2.5-0.5b-instruct`、`llama3.2-1b`），加载 <10 s，生成 15–30 tok/s |
| 准 | 3B–7B，但 CPU 上会慢到几十秒 |
| 不想下模型 | 模型路径留空，用本机已有的 Ollama 服务（就是备用通道） |

#### 已知限制

- 只送前 8 小节，避免提示词过长；长曲目请分段处理；
- 小模型容易「照抄示例」或「只写指令」，插件会检测并重试一次，仍失败就明确报错；
- 不支持 GPU（`GpuLayerCount = 0`），因为插件里没法保证 CUDA 运行时装好。

## 11. 已知限制（有意为之）

| 限制 | 说明 |
| --- | --- |
| 沙箱是准入而非隔离 | .NET 进程内没有硬安全边界：沙箱 = 默认禁用危险 API（装载前静态扫描）+ 只能走 `IPluginContext`。真要越界必须向用户申请无沙箱权限 |
| 不能扩展语法 | 解析器封闭；加语法要改内核（见 docs/09 §2.1） |
| 不能替换 UI 主体 | 只能往三个槽位**追加**控件，不能改动或移除内置控件 |
| 热重载有边界 | 见 §16：无 UI 引用的插件可完全回收，挂了控件的有残留风险，程序会提示 |
| 单个 `Id` 一个 | 重复会被忽略 |
| 同步装载 | 插件多了会拖慢启动（目前 1 个，无感） |

要加新钩子（例如「保存后处理」），做法是**新增接口 + 宿主新增调用点**，不要往 `IAttmPlugin` 里堆方法——那会破坏既有插件。

## 13. 排错

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 管理器里空列表 | 目录里没有 dll | 确认是 `plugins\`（不是 `plugin\`），dll 直接在目录下 |
| 显示「失败：装载失败」 | 依赖缺失 / 目标框架不对 | 插件要 `net10.0-windows`；把私有依赖一起放同目录 |
| 显示「失败：初始化失败」 | `Initialize` 抛异常 | 看消息；先把 `Initialize` 空实现验证能装载 |
| 勾上「已启用」但入口没出现 | 改动要重启 | 重启 ATTM |
| 导入按钮是灰的 | 没有导入型插件 | 插件要显式实现 `IImporterPlugin` |
| 插件加的控件不显示 | `CreateView` 抛异常被吞 | 看调试输出的 `[plugin]` 日志 |
| 拖放没反应 | 扩展名没被认领 | 核对 `Extensions` 的点与大小写 |

## 15. 沙箱：默认不让危险 API 进来

### 15.1 为什么不是「真隔离」

.NET 进程内没有安全边界（CAS 早已移除，AppDomain 也没了）。所以这里的沙箱是**准入式**的，三层：

| 层 | 手段 | 能挡住什么 |
| --- | --- | --- |
| 1 | 装载前**静态扫描程序集元数据** | 引用了 `System.IO.File`、`Process`、`HttpClient`、`Registry`、P/Invoke 等类型的插件**直接拒装** |
| 2 | 只通过 `IPluginContext` 提供能力 | 读文件走 `context.ReadFileBytes`（宿主检查存在性与 64 MB 上限） |
| 3 | 用户授权闸门 | 真要越界的插件必须声明并让用户点「是」 |

### 15.2 被禁止的类型（`PluginSecurityScanner`）

```text
System.IO.File / Directory / FileInfo / DirectoryInfo / FileStream / StreamWriter / StreamReader / FileSystemWatcher
System.Diagnostics.Process / ProcessStartInfo
System.Net.Http.HttpClient / System.Net.WebClient
System.Net.Sockets.Socket / TcpClient / UdpClient / System.Net.Dns
Microsoft.Win32.Registry / RegistryKey
System.Runtime.InteropServices.Marshal / NativeLibrary
System.Reflection.Emit.AssemblyBuilder
任何带 pinvokeimpl 的方法（P/Invoke）
```

> `System.IO.Path` **不在**禁止表里：它只是字符串处理，插件拿它拼文件名很常见。

命中即拒装，错误信息会列出具体命中的类型，例如：

```text
失败：沙箱禁止的 API：System.IO.File、System.Diagnostics.Process
```

### 15.3 沙箱插件怎么读文件

```csharp
public PluginImportResult Import(string path)
{
    var bytes = _context!.ReadFileBytes(path);   // 宿主读，检查存在性 + 64 MB 上限
    return new PluginImportResult(Convert(bytes));
}
```

内置的 MIDI 插件就是这么写的——所以它通过了扫描（有专门的测试守着这一点）。

### 15.4 申请无沙箱（需要用户确认）

```csharp
public sealed class PngExportPlugin : IExporterPlugin, ITrustRequestPlugin
{
    public string TrustJustification => "要把 PNG 写到用户选择的任意目录，需要直接的文件写入";
    // ...
}
```

流程：

```text
装载时发现插件实现 ITrustRequestPlugin
  ├─ 该 "id@version" 已在 ApprovedPlugins 里 → 直接按 Unrestricted 装载
  └─ 否则 → 记为 PendingApproval，**不调用 Initialize**
       └─ 主窗口启动时弹窗：「允许后它可以读写任意文件、访问网络、启动进程」
            ├─ 是 → 写入 ApprovedPlugins 并立即热重载
            └─ 否 → 保持待授权，插件管理器里可以看到理由
```

授权按 `id@version` 记录：**插件升级后需要重新确认**（版本变了就等于换了代码）。

### 15.5 边界（必须说清楚）

- 静态扫描看的是**元数据里有没有引用**，反射调用（`Type.GetType("System.IO.File")`）能绕过去；
- 沙箱挡不住恶意代码的通用手段，它挡的是「无意中越界」和「明显越界」；
- 真正的隔离要多进程 + IPC，本项目没做——需要的话把插件放进独立进程，用管道通信。

## 16. 热重载

### 16.1 怎么用

插件管理器 → **重新加载插件**。等价于：

```text
ShutdownAll()                     每个插件 Shutdown()
  → entries.Clear()               丢掉所有插件对象
  → UnloadContexts()              每个 ALC.Unload()（可回收上下文）
  → WaitForUnload()               GC 循环，最多 10 轮
  → LoadAll()                     重新扫描目录 + 静态体检 + 初始化
```

界面同步：清空工具栏 / 状态栏的插件控件 → 重新读聚合结果 → 重新装配按钮与控件。

### 16.2 关键实现细节（踩过的坑）

**卸载必须发生在独立栈帧里**。第一版把 `GC.Collect()` 直接写在 `Reload()` 里，结果永远收不掉——宿主方法帧里的局部变量（`foreach` 的 `context`）会被保守栈扫描当成存活引用。改成两个 `[MethodImpl(NoInlining)]` 辅助方法后立刻就能回收：

```csharp
[MethodImpl(MethodImplOptions.NoInlining)] private static void UnloadContexts(IEnumerable<AssemblyLoadContext> c);
[MethodImpl(MethodImplOptions.NoInlining)] private static bool WaitForUnload(IReadOnlyList<WeakReference> weak);
```

同理，**调用方也不能在重载前握着插件对象**——测试里一度因为 `host.Importers.Count` 生成的临时列表留在栈上而回收失败，改成重载后再取就好了。

### 16.3 回收结果会如实汇报

```csharp
public bool Reload();        // true = 所有旧上下文都已回收
public bool LastUnloadClean { get; }
```

- `true` → 状态栏提示「插件已重新加载」；
- `false` → 提示「部分上下文未能卸载，建议重启」（红字）。

装了**界面控件**的插件最容易回收失败：WPF 对象可能还挂在渲染队列或路由事件上。这种情况下功能已经重载成功（新插件在工作），只是旧程序集暂时留在内存里，重启即彻底干净。

### 16.4 什么时候需要重启

| 情况 | 热重载够用吗 |
| --- | --- |
| 改了插件 dll 的业务逻辑 | 够 |
| 改了插件的界面控件 | 大多数够，个别有残留 → 重启 |
| 改了宿主 `ATTM.exe` 本身 | 必须重启 |
| 改了 `config.json` 的 `DisabledPlugins` | 重启（管理器的勾选即重启语义） |
